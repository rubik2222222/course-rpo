# Домашнее задание: Примеры объектов и систем в модели OSI

**Курс:** Введение в компьютерные сети  
**Тема:** Модель OSI — привязка реальных объектов/систем/ошибок к уровням

---

## Задание

Взять 5 объектов, систем или ошибок и соотнести каждый с одним из уровней модели OSI.

---

## Модель OSI (напоминание)

| № | Уровень | Единица данных |
|---|---------|---------------|
| 7 | Прикладной (Application) | Сообщение |
| 6 | Представления (Presentation) | Сообщение |
| 5 | Сеансовый (Session) | Сообщение |
| 4 | Транспортный (Transport) | Сегмент |
| 3 | Сетевой (Network) | Пакет |
| 2 | Канальный (Data Link) | Кадр |
| 1 | Физический (Physical) | Бит |

---

## 5 примеров

---

### Пример 1 — Объект: Витая пара (кабель UTP Cat5e)

**Уровень OSI:** Уровень 1 — **Физический (Physical)**

**Обоснование:**  
Кабель витая пара — физическая среда передачи данных. Физический уровень отвечает за передачу потока бит по среде. Витая пара передаёт электрические сигналы, кодирующие нули и единицы, не вникая в смысл передаваемой информации. На физическом уровне описываются характеристики кабеля: пропускная способность (до 1 Гбит/с для Cat5e), затухание сигнала, длина сегмента (до 100 м).

```
Физический сигнал: __|‾‾|__|‾‾|__|‾‾|__ → биты: 0 1 0 1 0 1 0
```

---

### Пример 2 — Система: Ethernet-коммутатор (Switch)

**Уровень OSI:** Уровень 2 — **Канальный (Data Link)**

**Обоснование:**  
Ethernet-коммутатор работает на канальном уровне. Он оперирует кадрами (frames) и использует MAC-адреса для определения, на какой порт переслать кадр. Коммутатор строит таблицу MAC-адресов (CAM-table), сопоставляя адреса с портами. Это соответствует функциям канального уровня: физическая адресация, управление доступом к среде (MAC-подуровень).

```
Пример кадра Ethernet:
[ Преамбула | MAC dst | MAC src | EtherType | Данные | CRC ]
              ↑ именно с MAC-адресами работает коммутатор
```

---

### Пример 3 — Система: Маршрутизатор (Router)

**Уровень OSI:** Уровень 3 — **Сетевой (Network)**

**Обоснование:**  
Маршрутизатор работает на сетевом уровне. Он оперирует IP-пакетами и принимает решения о маршруте на основе IP-адресов назначения. Маршрутизатор объединяет разные сети (LAN, WAN) и обеспечивает их взаимодействие, что соответствует ключевой задаче сетевого уровня — создание составной сети и маршрутизация пакетов между ними.

```
Таблица маршрутизации:
Сеть назначения    | Маска      | Следующий хоп | Интерфейс
192.168.1.0        | /24        | 0.0.0.0       | eth0
10.0.0.0           | /8         | 192.168.1.1   | eth1
0.0.0.0 (default)  | /0         | 203.0.113.1   | eth2
```

---

### Пример 4 — Ошибка: TCP Connection Reset (RST)

**Уровень OSI:** Уровень 4 — **Транспортный (Transport)**

**Обоснование:**  
Флаг RST (Reset) в заголовке TCP-сегмента — это ошибка транспортного уровня. Она означает экстренное прерывание TCP-соединения. RST отправляется, когда одна из сторон получает сегмент, который не ожидала (например, попытка подключиться к закрытому порту, или соединение было сброшено брандмауэром). Транспортный уровень отвечает за установку соединений, надёжность и управление потоком.

```
Сценарий:
Клиент --[SYN]--> Сервер (порт 8080 закрыт)
Клиент <--[RST, ACK]-- Сервер
→ Соединение немедленно прервано
```

---

### Пример 5 — Объект: TLS-сертификат (HTTPS)

**Уровень OSI:** Уровень 6 — **Представления (Presentation)**

**Обоснование:**  
Протокол TLS (Transport Layer Security), лежащий в основе HTTPS, соответствует уровню представления модели OSI. Уровень представления отвечает за шифрование/дешифрование данных и согласование форматов представления информации. TLS обеспечивает именно это: шифрует данные перед передачей и расшифровывает при получении, а также аутентифицирует сервер с помощью X.509-сертификата. В лекции прямо указано, что TLS/SSL — пример уровня представления.

```
HTTP данные (открытый текст)
        ↓  [TLS шифрование — уровень представления]
Зашифрованный поток
        ↓  [TCP — транспортный уровень]
        ↓  [IP — сетевой уровень]
        ↓  [Ethernet — канальный уровень]
```
